# Лес

Текстовая игра для Telegram Mini App. Вы в лесу. Пишете что угодно, ведущий-ИИ сухо сообщает, что случилось.

```
— иду направо
07:52  Вы идёте по лесу.
— идём дальше
08:04  Вы встретили волка. Дать ему яблоко или ветку?
— дать ветку
08:05  Вас съел волк.
```

## Как устроено

ИИ не хранит мир. Он только читает ввод игрока и предлагает результат в JSON. Время, место, погоду, вещи при себе и смерть ведёт движок (`lib/engine.js`) и проверяет каждое предложение модели: нельзя отдать яблоко, которого нет, нельзя ходить после смерти, время не прыгает на сутки.

```
ввод игрока → buildAIContext → OpenRouter → parseAIReply → applyTurn → экран
```

| Файл | Что внутри |
|---|---|
| `lib/systemPrompt.js` | Голос ведущего. Тон игры правится здесь |
| `lib/engine.js` | Состояние мира и проверки. Работает и на сервере, и в браузере |
| `lib/openrouter.js` | Запрос к модели. Сменить модель или провайдера можно только тут |
| `lib/telegram.js` | Проверка подписи Telegram, чтобы чужие не тратили ваш ключ |
| `api/turn.js` | Серверная функция `POST /api/turn` |
| `index.html`, `src/` | Интерфейс |
| `src/demo.js` | Заготовленные ответы, если сервера нет |
| `scripts/dev.js` | Локальный сервер для `npm run dev` |

Состояние игры хранится у игрока в браузере и отправляется с каждым ходом. Сервер ничего не запоминает, база не нужна.

## Запуск

Нужен Node 22+. Устанавливать пакеты не нужно, зависимостей нет.

```bash
cp .env.example .env        # впишите OPENROUTER_API_KEY
npm test                    # проверки движка
npm run dev                 # игра на http://localhost:3000
npm run try                 # 20 свободных команд через настоящую модель, смотрите на тон
```

Добавьте `?debug` к адресу, чтобы увидеть технический лог хода: намерение, проверки, изменения состояния.

Если открыть `index.html` без сервера (или на GitHub Pages), игра сама перейдёт в демо-режим с заготовленными ответами.

## Деплой

API-ключ нельзя класть в репозиторий и во фронтенд, поэтому нужен хостинг с серверными функциями. Проще всего Vercel:

1. Залейте репозиторий на GitHub.
2. На vercel.com: Add New → Project → выберите репозиторий. Настройки сборки не нужны.
3. В Settings → Environment Variables добавьте `OPENROUTER_API_KEY`, `OPENROUTER_MODEL` и `TELEGRAM_BOT_TOKEN`.
4. Redeploy.

## Подключение к Telegram

1. В @BotFather создайте бота: `/newbot`.
2. `/newapp` → выберите бота → укажите адрес с Vercel (`https://ваш-проект.vercel.app`).
3. Токен бота положите в `TELEGRAM_BOT_TOKEN` на Vercel. С ним API отвечает только на запросы из Telegram.

## Модель

Модель задаётся переменной `OPENROUTER_MODEL`, по умолчанию `qwen/qwen3.8-27b:free`. Размышления модели выключены (`reasoning.enabled = false`): для ответа в одну фразу они только добавляют задержку. Если Qwen недоступен или упёрся в лимит бесплатных запросов, можно временно поставить `openrouter/free`: этот роутер сам выберет любую бесплатную модель. Актуальные ID смотрите на [openrouter.ai/models](https://openrouter.ai/models), бесплатные помечены `:free`. Если модель вернула ошибку, в логах Vercel будет строка `[turn] OpenRouter ответил 4xx`.

## Как править тон

Всё в `lib/systemPrompt.js`. Чаще всего помогает:

- добавить свой пример в блок ПРИМЕРЫ — модель копирует их интонацию сильнее, чем правила;
- поменять пропорции «скучно / событие / нелепость»;
- если модель начинает писать длинно, снизить `temperature` в `lib/openrouter.js`.
